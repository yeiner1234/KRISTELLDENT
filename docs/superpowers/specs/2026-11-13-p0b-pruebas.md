# P0b — Configurar pruebas automáticas (spec)

Diseño aprobado por el usuario (prompt del Sprint 3). Rama: `sprint3/p0b-pruebas`.

1. Instalar como devDependencies: vitest, jsdom, @testing-library/react, @testing-library/jest-dom, @testing-library/user-event.
2. Scripts en package.json: `"test": "vitest run"` y `"test:watch": "vitest"`.
3. `vitest.config.ts` en la raíz, separado de `vite.config.ts` (sin Tailwind ni React Compiler):
   ```ts
   import react from '@vitejs/plugin-react'
   import { defineConfig } from 'vitest/config'
   export default defineConfig({
     plugins: [react()],
     test: {
       environment: 'jsdom',
       setupFiles: ['./src/test/setup.ts'],
       include: ['src/**/*.test.{ts,tsx}'],
       env: { VITE_SUPABASE_URL: 'http://localhost:54321', VITE_SUPABASE_PUBLISHABLE_KEY: 'test-key' },
     },
   })
   ```
   Las variables evitan que `src/lib/supabase.ts` lance error al importarse en las pruebas.
4. `src/test/setup.ts`: importa `@testing-library/jest-dom/vitest` y llama a `cleanup()` en `afterEach`.
5. Pruebas de ejemplo (describe/it/expect/vi importados desde `vitest`, sin globals):
   - `src/utils/validation.test.ts`: DNI de 8 dígitos sí / 7 dígitos o con letra no; correo válido e inválido; teléfono de 9 dígitos sí / 8 no.
   - `src/components/common/Button.test.tsx`: llama a onClick al hacer clic (userEvent) y queda deshabilitado con `disabled`.
6. Las pruebas que dependan de Supabase mockean el módulo con `vi.mock('../lib/supabase')`. Ejemplo comentado en `src/test/README.md` de cómo mockear `supabase.from(...).select(...)` y `supabase.rpc(...)`.

## Criterios de aceptación
- `npm test`: 4 pruebas en verde.
- `npm run build` y `npm run lint` sin errores.
- Commit `test: configura Vitest y Testing Library`. Sin push.
